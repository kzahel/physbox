authority-still binary32 trajectory when the unchanged exact recurrence is

## Frozen event families and event keys

Every scalar discrete event has a canonical key containing source, completed
outer step, substep, pass, authority visit ordinal, generational body pair,
and point feature pair where applicable. Event records contain discrete tokens
and the first downstream impulse/body delta, while continuous values remain
diagnostic payload and are never route inputs.

The only routable families are:

1. `contact-admissibility-and-point-count`: pair admitted, manifold admitted,
   point count, and locally available point ordinal;
2. `reference-owner-and-authority-feature-identity`: reference owner, face,
   normal orientation token, and complete local feature pair;
3. `separation-positive-and-speculative-branch`: the exact
   `separation > 0` branch selected at each normal projection;
4. `unilateral-active-set-projection`: whether accumulated normal projection
   selects the native candidate or the zero boundary;
5. `warm-cache-match-and-impulse-ownership`: hit/miss, matched generational
   key, and which locally available prior impulse record owns the seed; and
6. `support-graph-color-and-overflow-order`: overflow/color class and stable
   visit rank for each locally available contact.

A difference in continuous position, velocity, separation, coefficient,
impulse magnitude, or energy is not itself an event divergence. A1 must name
the earliest differing discrete token and then the earliest downstream
continuous delta caused after that token. If the earliest causal discrete
token cannot be expressed by one of the six families, S16 stops at the first
human checkpoint without A2.

## Diagnostic routing semantics

A2 exchanges one complete event family at a time in both directions between
`exact-s12-f32` and `full-solve-f64`:

- `f64<-f32/F`: full-solve binary64 retains its native continuous arithmetic,
  equations, state, coefficients, and locally generated payloads while family
  `F` takes the immutable binary32 endpoint's discrete tokens; and
- `f32<-f64/F`: exact binary32 retains its native continuous recurrence while
  family `F` takes the immutable binary64 endpoint's discrete tokens.

Routing may choose only among payloads computed locally by the receiving lane.
It may not copy anchors, normals, positions, velocities, coefficients,
separations, impulses, cache values, body state, or another continuous value
from the owner stream. If an owner token refers to no locally available
choice, the arm fails closed as `owner-choice-unavailable`; it must not invent
a contact or source-copy the missing payload. Owner streams are retained from
unrouted endpoint runs and do not change in response to a routed trajectory.

Every routed arm runs both depths twice, replays exactly, remains finite, and
reports the unchanged S12 predicate vector. A family is individually causal
only when `f64<-f32/F` strictly improves the first failing predicate without
introducing an earlier failure and `f32<-f64/F` either changes the same first
event/downstream path or records a fail-closed unavailable owner choice. This
is a routing rule, not an acceptance-band change.

## Minimal sufficient event structure

A3 considers only individually causal families from A2. It enumerates their
subsets in increasing cardinality and fixed family order, sourcing those
families from the retained binary32 event stream into full binary64. It stops
opening larger cardinalities after one cardinality contains a subset that
passes every unchanged depth-11 and depth-16 authority predicate, but completes
all subsets at that cardinality to avoid a first-winner artifact.

The minimal sufficient measured structure is every qualifying subset at the
smallest qualifying cardinality. Each reported minimal set must replay exactly
at both depths; every proper routed subset must have a verified failure. If no
subset qualifies, the result is `no-declared-routed-event-structure`. Routing
failure is evidence and cannot be repaired by continuous source copy, a new
event family, a changed recurrence, or a changed band.

The A3 package is a mandatory human stop whether the result is positive or
negative. It contains no formulation, kernel, product candidate, or promotion
recommendation.

## A4 static colored-GPU representability

After human release of the A3 checkpoint, A4 statically maps only the measured
minimal event owner to existing bounded portable WGSL storage, event
production, colors, overflow-first order, indirect work, and synchronization.
The verdict is exactly one of `exactly-representable`,
`not-exactly-representable`, or `no-structure-to-map`.

An exact mapping must preserve one GPU world, fail-closed capacity, existing
portable WebGPU limits, and no CPU feedback, source-copy state, global sort,
subgroup requirement, device-wide barrier, fallback engine, or unbounded
synchronization. A4 is static analysis only: no WGSL candidate, GPU execution,
timing, capacity fixture, cross-host run, or product change is authorized.
